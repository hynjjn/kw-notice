# 0001. 사용자 인증 정보와 개인 데이터는 서버에 두지 않는다

- 상태: 채택
- 날짜: 2026-10-06

## 배경

KW Notice를 "나만의 학교 에이전트"로 키우려면 KLAS에 로그인해 과제, 시간표, 성적을 가져와야
한다. 다른 학생에게도 배포한다고 가정하면, 서버가 학생들의 KLAS 비밀번호를 받는 구조가 된다.

이 문제는 앞선 프로젝트 두 곳에서 이미 만났다.

**MailAlphaMail**(팀 프로젝트, 중단)은 여러 회사의 메일을 한곳에서, 어디서든, 설치 없이
보는 웹 서비스였다. 서버가 사용자의 메일 앱 비밀번호를 받아 IMAP에 접속했다. 암호화는 꽤 단단했다.

- 로그인 비밀번호에서 Argon2id로 KEK를 만들고, 사용자마다 랜덤 DEK를 KEK로 감싸 DB에 둔다
- 앱 비밀번호는 DEK로 AES-GCM 암호화한다
- 로그인하면 풀린 DEK를 Redis에 30분, AWS KMS로 감싼 DEK를 24시간 둔다

DB만 털려서는 비밀번호가 나오지 않는다. 그래도 IMAP에 접속하려면 서버가 결국 평문을 쥐어야
한다. Redis에 풀린 키가 있는 동안, 그리고 KMS로 감싼 키가 남아 있는 동안 서버는 사용자 없이도
복호화할 수 있다. 암호화는 "저장된 상태"를 지킬 뿐 "운영자를 믿어 달라"에서 벗어나게 해 주지
못했다. "어디서든, 설치 없이"라는 제품 목표가 서버 보관을 요구했기 때문에, 구현을 바꿔서는
풀 수 없는 문제였다.

**MarshMallow**(팀 프로젝트)는 사용자의 토스증권 API 키를 서버가 받아 KMS로 암호화해 저장했다.
같은 구조이고, 이번에는 주문 권한까지 걸려 있었다.

반대로 이 문제를 피한 예도 있다.

- **Apple Mail, Thunderbird**: 중간 서버가 없다. 기기가 메일 서버에 직접 붙고, 인증 정보는
  OS 키체인이나 자체 암호화 저장소에 둔다
- **KLAS+**(광운대 학생이 만든 KLAS 앱, MIT): 앱이 KLAS에 직접 로그인한다. KLAS의
  `SelectScrtyPwd.do`가 돌려준 암호화 비밀번호만 iOS 키체인과 Android Keystore에 둔다.
  평문 비밀번호는 저장하지 않는다
- **KLAS GPT**(KLAS+의 AI 기능): 도구를 기기에서 실행하고 AI 서버(Cloudflare Worker)에는
  결과만 보낸다. 세션 토큰은 AI 서버로 가지 않는다. 다만 웹뷰라 CORS 때문에 KLAS 호출이
  자기 서버의 `/api/proxy`를 지나간다(저장은 하지 않는다). 성적 같은 도구 결과는 OpenAI로 간다

## 결정

**특정 사용자가 피해를 보는 데이터는 서버에 두지 않는다.**

- KLAS 아이디, KLAS가 암호화한 비밀번호, 세션 토큰은 사용자 PC의 OS 키체인에 둔다.
  평문 비밀번호는 저장하지 않는다
- KLAS 데이터, 메모리, 대화 기록은 사용자 PC에 둔다
- KLAS 호출은 사용자 PC에서 직접 한다. 프록시 서버를 거치지 않는다
- 서버에는 공지처럼 모두에게 같은 공개 데이터와 운영자 자신의 키만 둔다

## 검토한 대안

- **서버에 암호화해서 저장**: MailAlphaMail, MarshMallow 방식. 저장 상태는 지키지만 서버가
  평문을 다뤄야 하는 순간을 없애지 못한다. 학생 개발자가 "운영자를 믿어 달라"를 보장할 방법이 없다
- **웹앱 + 무저장 프록시**: KLAS GPT 방식. 저장은 안 하지만 토큰이 서버를 지나간다. 사용자는
  프록시가 로그를 남기지 않는다는 것을 믿어야 한다
- **OAuth**: KLAS에는 없다

## 결과

얻는 것

- 서버가 털려도 사용자 인증 정보와 개인 데이터는 나오지 않는다
- 운영자를 믿어 달라고 할 필요가 없다. 코드를 공개하면 저장하지 않는다는 것을 누구나 확인할 수 있다

잃는 것

- 브라우저 웹앱으로는 만들 수 없다. 웹 페이지는 CORS 때문에 KLAS에 직접 요청하지 못한다.
  설치하는 앱이 필요하다([0002](0002-desktop-with-electron.md))
- 기기 간 동기화가 어렵다. 필요해지면 키를 기기가 들고 서버는 암호문만 갖는 종단간 암호화로 한다.
  MailAlphaMail과의 차이는 키를 누가 만들고 들고 있느냐다
- 클라우드 모델을 쓰면 개인 데이터가 서버 중계를 "지나가는" 일은 남는다. 이건 로컬 모델로
  줄인다([0003](0003-agent-loop-on-client.md), [0004](0004-local-model-via-ollama.md))

## 지킬 것

- KLAS 로그인이 2번 넘게 실패하면 KLAS가 캡차를 요구한다. 자동으로 다시 시도하지 않고 사용자에게 넘긴다
- 로그에 비밀번호, 토큰, 성적을 남기지 않는다
