# 0004. 로컬 모델은 Ollama로 연결한다

- 상태: 채택, v2에서 적용
- 날짜: 2026-10-06

v1은 Gemini API(서버 중계)만 쓴다. v1에서 만드는 제공자 인터페이스([0003](0003-agent-loop-on-client.md))
위에 v2에서 `OllamaProvider`를 더한다.

## 배경

[0003](0003-agent-loop-on-client.md)대로 하면 클라우드 모델을 쓸 때 KLAS 도구 결과가 서버 중계와
Gemini를 지나간다. 성적이나 학적처럼 민감한 데이터를 기기 밖으로 보내지 않으려면 사용자 PC에서
도는 모델이 필요하다.

비용도 이유다. 2026-10-05 하루 Gemini 사용료는 450원이었고, 그날은 AI 기능을 처음 붙이며 테스트가
몰린 날이었다. 지금 규모로는 작지만 사용자가 늘면 중계 비용이 같이 는다.

## 결정

**모델 제공자로 Ollama HTTP API를 쓴다.** 앱은 Ollama 주소 하나만 알면 된다.

- 개발: 개발 맥이나 집 NVIDIA 게이밍 노트북의 Ollama. 노트북은 Tailscale로 붙는다
- 배포: 사용자 PC의 Ollama를 쓰거나, 앱에 node-llama-cpp를 내장한다. node-llama-cpp는
  Electron `utilityProcess`에서 돌려 앱이 멈추지 않게 하고, 모델 파일은 사용자가 켤 때 용량을
  보여 주고 동의를 받은 뒤 내려받는다
- 선택: 지원되는 Mac(macOS 26, M1 이상)에서는 Apple Foundation Models를 Swift sidecar로 붙인다

llama.cpp 계열은 같은 모델 파일(GGUF)로 NVIDIA(CUDA)와 Mac(Metal)에서 모두 돈다. 특정 하드웨어에
묶이지 않는다.

## Ollama 위치에 따른 분류

기술은 같아도 데이터가 누구 손에 가느냐가 다르다.

| 위치 | 분류 |
| --- | --- |
| 사용자 PC(`localhost`) | 로컬 |
| 사용자 소유 기기(Tailscale 등 사설망) | 로컬 |
| 사용자가 빌린 GPU 서버 | 원격 |
| 운영자가 빌려 여러 사용자에게 제공 | 원격. LLM 중계와 같은 구조다 |

"민감 데이터는 로컬만" 설정에서는 로컬로 분류된 주소만 쓴다. 사용자가 원격 주소를 넣으면
"이 주소로 데이터가 전송된다"고 알린다.

## 사양별 경로

| 사양 | 경로 |
| --- | --- |
| NVIDIA 8GB 이상, Apple Silicon 16GB 이상 | 7~8B 모델로 에이전트 전체를 로컬에서 |
| 그보다 낮음 | 3~4B 모델로 민감한 결과 읽기와 답 쓰기만. 도구 고르기는 클라우드 모델이 질문과 도구 이름만 보고 한다 |
| 로컬 불가 | 클라우드. 민감 도구는 기본으로 꺼 둔다 |

작은 모델은 어떤 도구를 부를지 판단하는 데 약하지만, 주어진 데이터를 정리하는 일은 잘한다.
그래서 판단과 읽기를 나눈다. 기준 사양과 모델은 평가 세트로 정한다.

## 지킬 것

- Ollama에는 인증이 없다. 포트를 인터넷에 열지 않는다. 원격은 사설망 안에 두거나 인증 프록시를 앞에 세운다
- 앱이 띄우는 로컬 모델 서버는 `127.0.0.1`에만 열고, 무작위 포트와 API 키를 쓴다
- 모델 파일은 원 저작자의 공식 배포처에서 받고 해시를 확인한다

## 결과

얻는 것

- 민감한 데이터를 기기 밖으로 보내지 않는 경로가 생긴다
- 개발 중에는 운영자 비용 없이 실험할 수 있다

잃는 것

- 로컬 모델은 클라우드보다 한국어 품질이 낮고 컨텍스트가 짧다. 도구 결과를 줄여서 넘겨야 한다
  (공지 본문 대신 요약)
- 모델 파일이 수 GB다. 저사양 PC에서는 쓸 수 없다
