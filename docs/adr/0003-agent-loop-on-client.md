# 0003. 에이전트 루프는 클라이언트에서 돌고, 서버는 LLM 중계만 한다

- 상태: 채택
- 날짜: 2026-10-06

## 배경

지금 `/api/chat`은 서버 안에서 다 한다. Gemini SDK의 자동 도구 호출(`automatic_function_calling`)이
`search_notices`, `get_notice`, `remember`, `forget`을 불러 가며 답을 만든다
(`backend/app/chat/service.py`).

KLAS 도구가 붙으면 이 구조가 맞지 않는다. KLAS 데이터와 토큰은 사용자 PC에 있으므로
([0001](0001-credentials-stay-on-device.md)) 서버가 KLAS 도구를 실행할 수 없다. 로컬 모델을 쓰면
모델도 사용자 PC에 있다. 결국 루프와 도구 실행이 사용자 PC로 와야 한다.

## 결정

- **에이전트 루프는 `packages/core`(TypeScript)에서 돈다.** Electron 앱이 실행한다
- **도구는 둘로 나눈다.**
  - 공개 도구(`search_notices`, `get_notice`): 서버 공지 API를 부른다
  - 개인 도구(KLAS, 메모리): IPC로 Electron main을 부른다
- **도구 정의는 JSON 스키마 데이터로 둔다.** 모델 제공자마다, 언어마다 다시 쓰지 않는다
- **모델 제공자는 인터페이스 뒤에 둔다.** `generate(messages, tools)`가 답이나 도구 호출을 돌려준다
  - `RelayProvider`: 서버 LLM 중계를 거쳐 Gemini
  - `OllamaProvider`: Ollama([0004](0004-local-model-via-ollama.md)). v2에서 더한다
- **서버 `/api/chat`은 LLM 중계로 줄인다.** 받은 메시지와 도구 정의를 Gemini에 넘기고 결과를
  돌려준다. 아무것도 저장하지 않는다
- **쓰기 도구는 실행 전에 사용자 승인을 받는다.**

## 중계를 열 때 지킬 것

중계는 운영자의 Gemini 키로 돈다. 막지 않으면 누구나 쓰는 공짜 Gemini 프록시가 된다.

- 기기 단위 토큰으로 인증한다
- 사용량을 세 겹으로 제한한다: 기기별, IP별, 서비스 전체(분당, 하루). 기기 ID나 IP를 바꿔도
  전체 상한은 그대로다. KLAS GPT도 이렇게 한다
- 최대 토큰, 허용 도구 목록, 시스템 프롬프트는 서버가 고정한다. 클라이언트가 바꾸지 못한다
- 요청 본문을 로그에 남기지 않는다

## 검토한 대안

- **서버가 루프를 돌리고 KLAS 데이터를 미리 받아 둔다**: 서버가 개인 데이터를 갖게 된다. 0001과 충돌한다
- **서버가 루프를 돌리고, 개인 도구만 클라이언트에 되물어 실행한다**: 가능하지만 루프가 서버와
  클라이언트에 걸쳐 있어 복잡하다. 로컬 모델로 바꿀 때 다시 옮겨야 한다
- **SDK 자동 도구 호출을 계속 쓴다**: 편하지만 Gemini에 묶인다. 루프를 직접 짜야 제공자를 바꿀 수 있다

## 결과

얻는 것

- 모델을 바꿀 때 제공자 하나만 갈아 끼운다. 루프, 도구, 화면은 그대로다
- 서버는 개인 데이터를 저장하지 않는 무상태 중계가 된다

잃는 것

- 클라우드 모델을 쓰면 KLAS 도구 결과가 중계를 지나 Gemini로 간다. 저장하지 않더라도 지나가는
  것은 남는다. 처리방침에 적고, 보내는 양을 줄인다(이번 주 과제를 물으면 이번 주 과제만 보낸다)
- 루프를 Python에서 TypeScript로 옮기는 일이 생긴다

## 첫 단계

루프를 옮기기 전에 서버 안에서 먼저 모양을 잡는다. SDK 자동 호출을 직접 짠 루프로 바꾸고,
제공자 인터페이스와 JSON 스키마 도구 정의를 만든다. 기능은 지금과 같다.
