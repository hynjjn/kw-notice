# 0005. 메모리와 대화 기록을 기기로 옮긴다

- 상태: 채택
- 날짜: 2026-10-06
- 바꾸는 것: `user_memories` 테이블과 `/api/memories` (ae33926)

## 배경

AI 채팅은 "새 대화"를 누르면 맥락이 사라졌다. 같은 설명을 반복하느라 토큰이 낭비된다는 문제에서
메모리 기능을 만들었다(ae33926).

- 모델이 학과, 학번, 신분, 관심 분야를 `remember` 도구로 저장하고, 질문할 때마다 시스템 프롬프트에 붙인다
- 저장 위치는 서버 Postgres의 `user_memories` 테이블이다

만들 때는 단일 사용자 MVP였다. 이후 [0001](0001-credentials-stay-on-device.md)에서 경계를 정하고
보니, 학과나 학번은 특정 사용자의 개인 정보라 서버에 두면 안 되는 쪽이다.

대화 기록도 같다. 지금은 프론트 메모리에만 있어 새로고침하면 사라지고, 서버는 저장하지 않는다.
KLAS GPT는 질문과 답을 서버(Durable Object)에 30일 저장해서 이 문제를 푼다.

## 결정

- **메모리를 사용자 PC의 SQLite로 옮긴다.** `remember`, `forget`은 개인 도구가 되어 IPC로
  Electron main을 부른다([0003](0003-agent-loop-on-client.md))
- **대화 기록도 사용자 PC의 SQLite에 저장한다.** 지난 대화 목록을 보고 다시 열 수 있게 한다
- 서버의 `user_memories` 테이블과 `/api/memories`는 옮긴 뒤 지운다

메모리를 붙이는 방식(시스템 프롬프트에 목록으로 붙이기, 30개 상한, 저장 기준 프롬프트)은 그대로 쓴다.
메모리가 차지하는 토큰은 실측으로 모델 호출당 기억 3개에 약 510, 30개에 약 1,060이다.

## 결과

얻는 것

- 서버가 개인 데이터를 하나도 저장하지 않는다
- "새 대화"를 눌러도 지난 대화가 남는다. 처음 문제였던 토큰 낭비도 같이 준다

잃는 것

- 기기를 바꾸면 메모리와 대화가 따라오지 않는다. 필요해지면 종단간 암호화 동기화를 붙인다
- 이미 만든 서버 쪽 코드를 옮기는 일이 생긴다

처음에 서버에 두었다가 경계를 정하면서 옮기는 것이라, 이 기록을 남겨 둔다.
