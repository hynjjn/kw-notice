# 목표 구조

지금 KW Notice는 브라우저용 React와 FastAPI 서버로 되어 있다. 이 문서는 KLAS 연동과
로컬 모델까지 들어간 다음 구조를 정리한다. 결정마다의 이유는 [adr/](adr/)에 있다.

한 줄로 줄이면 이렇다. **모두에게 같은 것은 서버에, 사용자마다 다른 것은 사용자 PC에 둔다.**

## 전체 그림

```
┌─ 사용자 PC: Electron 앱 ───────────────────────────────────────┐
│                                                                │
│  React 화면 (지금 frontend/ 재사용)                              │
│   공지 목록, 읽기, 채팅, 메모리, 설정                              │
│        │                                                       │
│  packages/core (TypeScript, 플랫폼 무관)                          │
│   ├ 에이전트 루프                                                │
│   ├ 도구 정의 (JSON 스키마)                                       │
│   ├ 모델 제공자: RelayProvider | OllamaProvider                   │
│   └ "기기 기능" 인터페이스 ──────────┐                             │
│                                    │ IPC (정해진 요청만)           │
│  Electron main (Node) ◀────────────┘                             │
│   ├ KLAS 로그인, KLAS API 호출 (프록시 없이 직접)                    │
│   ├ 키 보관: safeStorage (OS 키체인)                               │
│   └ SQLite: 메모리, 대화 기록, KLAS 캐시                            │
│                                                                │
└──────┬──────────────────────┬──────────────────────┬───────────┘
       │ 공지 검색, 상세        │ 클라우드 모델 호출       │ 로컬 모델 호출
       ▼                      ▼                      ▼
┌─ 서버 ────────────────────────────┐   ┌─ Ollama ──────────────────┐
│ FastAPI + Postgres (지금 그대로)   │   │ 사용자 PC (localhost)      │
│  ├ 크롤러, 첨부 추출, 요약          │   │ 또는 사용자 소유 기기        │
│  ├ 공지 API                       │   │ (Tailscale)               │
│  └ LLM 중계 ──▶ Gemini            │   └───────────────────────────┘
│     무상태, 인증, 사용량 제한        │
└──────────────────────────────────┘
                                      KLAS ◀── Electron main만 직접 접속
```

## 층마다 맡는 일

| 층 | 맡는 일 | 맡지 않는 일 |
| --- | --- | --- |
| 서버 (FastAPI, Postgres) | 공지 크롤링, 첨부와 포스터 글자 추출, 요약, 공지 검색 API, LLM 중계 | 사용자 인증 정보, 개인 데이터 저장 |
| Electron main | KLAS 로그인과 호출, 키 보관, SQLite, 로컬 모델 연결, 앱 배포와 업데이트 | 화면 |
| packages/core | 에이전트 루프, 도구 정의, 모델 제공자, 서버 API 클라이언트 | 플랫폼별 코드 |
| React | 화면, 사용자 승인 카드 | 비밀 보관, KLAS 직접 호출 |

React는 웹뷰 안에서 돈다. 공지 본문 HTML, 첨부 미리보기, 모델이 만든 마크다운처럼 외부에서
온 내용을 그리므로, 비밀은 React가 손댈 수 없는 main에만 둔다. React는 IPC로 "이번 학기 과제
목록"처럼 정해진 요청만 하고 결과 데이터만 받는다. 토큰은 받지 않는다.

## 데이터가 있는 곳

| 데이터 | 위치 | 새면 누가 피해를 보나 |
| --- | --- | --- |
| 공지, 첨부 텍스트, 요약 | 서버 Postgres | 없음. 공개 정보 |
| 운영자 Gemini 키 | 서버 | 운영자(비용) |
| KLAS 아이디, KLAS가 암호화한 비밀번호, 세션 토큰 | Electron main, OS 키체인 | 그 사용자 |
| KLAS 데이터(과제, 시간표, 성적), 메모리, 대화 기록 | 사용자 PC SQLite | 그 사용자 |

나누는 기준은 마지막 열이다. 특정 사용자가 피해를 보는 데이터는 서버에 두지 않는다
([ADR 0001](adr/0001-credentials-stay-on-device.md)).

## 질문이 흘러가는 길

**공지 질문**("이번 주 장학금 마감 알려줘")

1. React가 질문을 에이전트 루프에 넘긴다
2. 모델이 `search_notices`를 고른다
3. 루프가 서버 공지 API를 부르고, 결과를 모델에 넘겨 답을 받는다

공개 데이터라 클라우드 모델로 가도 된다.

**KLAS 질문**("이번 주 과제 정리해 줘")

1. 모델이 `klas_tasks`를 고른다
2. 루프가 IPC로 main에 요청하고, main이 KLAS에서 과제 목록을 받아 돌려준다
3. 결과를 누가 읽는지는 설정이 정한다
   - 로컬만: Ollama가 읽고 답을 쓴다. 기기 밖으로 나가지 않는다
   - 클라우드 허용: 서버 중계를 거쳐 Gemini가 읽는다. 서버는 저장하지 않는다

**쓰기 도구**(일정 추가 등)는 실행 전에 React가 승인 카드를 띄우고, 사용자가 허락해야 main이
실행한다. 모델이 읽는 공지나 게시글에 지시문이 숨어 있어도(prompt injection) 사람 확인 없이
되돌릴 수 없는 일이 일어나지 않게 하기 위해서다.

## 모델 고르기

v1은 Gemini(서버 중계)만 쓴다. 아래 경로는 v2에서 로컬 모델이 들어온 뒤의 것이다.

| 사양 | 경로 |
| --- | --- |
| 로컬 모델 충분(7~8B, NVIDIA 8GB 이상 또는 Apple Silicon 16GB 이상) | 에이전트 전체를 로컬에서 |
| 로컬 모델 작음(3~4B) | 도구 고르기는 클라우드, 민감한 결과 읽기와 답 쓰기는 로컬 |
| 로컬 불가 | 클라우드. 민감 도구는 기본으로 꺼 두고 사용자가 켤 수 있다 |

Ollama 주소가 사용자 PC나 사용자 소유 기기가 아니면 원격 모델로 분류한다. "로컬만" 설정에서는
원격 모델을 쓰지 않는다([ADR 0004](adr/0004-local-model-via-ollama.md)).

## 지금 코드에서 바뀌는 것

| 지금 | 바뀐 뒤 |
| --- | --- |
| `/api/chat`이 Gemini 호출과 도구 실행을 다 한다 | LLM 중계만 한다. 루프는 `packages/core`로 간다 |
| `/api/memories`, `user_memories` 테이블 | 지운다. 기기 SQLite로 옮긴다 |
| 대화는 새로고침하면 사라진다 | 기기 SQLite에 남는다 |
| 서버는 개발 맥의 `127.0.0.1`에서만 돈다 | 공개 배포한다. HTTPS, 인증, 사용량 제한이 붙는다 |
| 프론트는 브라우저 SPA이고 S3 배포를 계획했다 | Electron 앱이다. 서명과 자동 업데이트가 붙는다 |
| KLAS 연동 없음 | main에 KLAS+의 로그인 흐름을 옮긴다 |

크롤러, 첨부 추출, 요약, 공지 검색은 그대로 남는다.

## 버전 계획

| 버전 | 범위 | 모델 |
| --- | --- | --- |
| v1 | Electron 앱, KLAS 연동, 메모리와 대화를 기기로 | Gemini API(서버 중계) |
| v2 | 로컬 모델, "민감 데이터는 로컬만" 설정, 사양별 경로 | Ollama 추가 |
| 나중 | 모바일(Capacitor) | 중계, 지원 iPhone은 Apple Foundation Models |

**v1**

1. **에이전트 루프 정리**: Gemini SDK의 자동 도구 호출을 직접 짠 루프와 제공자 인터페이스로 바꾼다. 아직 서버 안에서 한다
2. **루프를 `packages/core`로**: 서버 `/api/chat`을 LLM 중계로 줄인다
3. **Electron 껍데기**: React를 띄우고 main과 IPC 경계를 만든다. 메모리와 대화를 SQLite로 옮긴다
4. **KLAS 연동**: 로그인, 키 보관, 과제와 시간표 도구
5. **배포 준비**: 서버 공개 배포와 사용량 제한, 앱 서명과 업데이트

v1에는 로컬 모델이 없어서 KLAS 도구 결과가 항상 중계를 지나 Gemini로 간다. 그래서 v1에서도
다음 두 가지는 넣는다.

- 민감 도구(성적, 석차, 학적 등)를 끌 수 있는 설정. 기본값은 꺼짐
- 처리방침에 "KLAS 도구 결과가 서버 중계를 지나 Gemini로 전송되며, 서버는 저장하지 않는다"고 적기

제공자 인터페이스는 v1에서 만들어 두므로 v2는 `OllamaProvider`를 더하는 일이 된다.

**v2**

6. **OllamaProvider**: 평가 세트로 모델을 고른다
7. **로컬 경로**: "민감 데이터는 로컬만" 설정, 사양별 경로, Ollama 주소의 로컬과 원격 분류

**나중**

8. **모바일**: Capacitor 어댑터. iPhone은 Apple Foundation Models를 선택지로 둔다

## 평가 세트

질문 20~30개와 기대 답을 모아 두고, 모델이나 프롬프트를 바꿀 때마다 같은 질문으로 정답률과
응답 시간을 잰다. 로컬 모델 선택, 사양별 경로 기준, 클라우드와 로컬의 역할 분담을 이 숫자로
정한다.
